# 브랜드 파트너 허브 — 비판적 리뷰 v0

작성 2026-07-12 · 대상: briefing 0.0.19~0.0.21 (기획서·v2 설계·구현 전체)
관점: 제작 의도("브랜드사가 올리면 AI가 정리하고 우리는 검수만 — 업무 획기적 절감")에
대한 객관·비판 평가 + 사내 완성 → SaaS 판매 수준까지의 경로. 자화자찬 금지 기준으로 작성.

## 0. 총평

| 축 | 등급 | 한 줄 판정 |
|---|---|---|
| 아키텍처·설계 | **A-** | 업계 검증 패턴(Akeneo SDM형 온보딩 + Salsify형 완성도)과 정직성 원칙의 결합 — 방향은 맞다 |
| 구현 품질 | **B+** | 테스트 438·실브라우저 검증·정직한 실패 상태는 상위 수준. 단 라이브 AI 경로 미실행, DB 실경로 미검증 |
| **파일럿 투입 준비도** | **C+** | 시연은 지금도 가능. 실제 파트너에게 링크를 주려면 §3의 보안 3건 + 데이터 2건이 선행돼야 함 |
| **SaaS 판매 준비도** | **D** | 단일 테넌트·고정 스키마·과금 없음 — 구조 변경이 필요한 단계. 단, 팔릴 "모서리"는 이미 존재(§5) |

**핵심 판정**: 지금 만들어진 것은 "잘 설계된 파일럿 스캐폴드"다. 뼈대(거버넌스·정직성·
프로바이더 추상화·인간 게이트)는 SaaS까지 들고 갈 자산이고, 살(사전 데이터·골든셋·보안
경화·루프 완성)은 아직 얇다. 가장 큰 리스크는 기술이 아니라 **가치 증명이 미측정**이라는
것 — "업무 획기적 절감"은 아직 숫자로 입증된 적이 없다.

## 1. 제작 의도 대비 달성도

의도: ①브랜드사 셀프서브 업로드 ②AI 자동 분석·분류·최적화 저장 ③운영자는 검수만
④컴플라이언스 내장 ⑤업무 시간 30–60분/제품 → 3–5분.

| 의도 | 달성도 | 근거 |
|---|---|---|
| ① 셀프서브 업로드 | **85%** | 4레인·검증·정직한 실패까지 완성. 빠진 것: 업로드한 파일을 다시 볼 수 없음(§3-P6), 알림 없음 |
| ② AI 분석·분류·저장 | **60%** | 파이프라인 구조·자동화·스키마는 완성. 그러나 **드라이런만 실행됨** — 실문서 정확도 0건 측정 |
| ③ 검수만 하는 운영자 | **55%** | 승인/반려 게이트는 있으나 **검수에 필요한 정보가 부족**(원본·사진 대조 불가, §3-P5) — 지금은 "반쯤 눈감고 승인"에 가까움 |
| ④ 컴플라이언스 내장 | **40%** | 구조(신호 등급·면책·출처 기록)는 옳으나 **데이터가 데모 수준**: INCI 사전 ~80종(CosIng은 ~3만), 규제 룰 8물질. 실카탈로그를 넣으면 대부분 unmatched |
| ⑤ 업무 절감 수치 | **0%** | 골든셋·실측 없음. 이 시스템의 존재 이유가 아직 가설 상태 |

## 2. 잘된 것 (지키면서 가야 할 자산)

1. **정직성이 코드에 박혀 있다.** 추측 대신 unmatched/needs_review, 가짜 토큰·죽은 링크
   생성 금지, DB-off 시 소비자 표면은 정직한 503, "검증만 됨" 칩. 이건 나중에 붙이기
   어려운 문화 자산이고, B2B 신뢰 상품의 핵심 차별점이다.
2. **인간 게이트 + 감사 추적.** 자동 확정이 어디에도 없고, 승인/반려가 결정자·사유와 함께
   기록된다(partner_review_decision). SaaS 셀링 포인트가 되는 구조.
3. **구조적 누출 차단.** 필드 화이트리스트로 internal_memo·공급가·타사 데이터·storage_path·
   모델명이 파트너 응답에 존재할 수 없게 만들었고, 테스트가 이를 고정한다.
4. **프로바이더 추상화 + 듀얼 게이트 + 비용 상한 사상.** 모델 교체가 config 1줄, 드라이런
   기본이라 개발·테스트가 비용 0. Gemini 3.5 Pro 맞대결 준비 완료.
5. **기존 시스템과의 정합.** product_catalog·claims-check·잡큐·정산까지 한 몸 — 포털이
   섬이 아니라 파이프라인의 입구다. (SaaS 분리 시엔 이 결합이 역으로 비용이 됨, §5)
6. **테스트·검증 규율.** 438 테스트, 실브라우저 E2E, 실검증에서 잡은 CORS 버그 2건이
   회귀 테스트로 남음. 스모크가 카피 문구(정직성 문구 포함)까지 고정.
7. **벤치마킹이 실제 설계에 반영됨.** Akeneo(벤더는 편하게, 정제는 우리가)·Salsify(완성도
   스코어)·Amazon VC(즉시 오류 리포트) — 흉내가 아니라 소화된 형태.

## 3. 문제와 부족 (심각도순)

### 심각 — 실파트너 투입 전 반드시 해결

- **P1. 토큰 만료 미구현 (설계-구현 격차).** 설계 §8은 "짧은 만료+회전"이라 썼지만 구현엔
  만료가 없다(코드에 expiry 0건). 쓰기 권한이 있는 영구 토큰이 URL 쿼리로 다닌다 —
  프록시/서버 로그에 남는 형태. 최소: 만료 컬럼+검사, 토큰 해시 저장(현재 평문), 로그
  마스킹. (referrer 유출은 no-referrer로 이미 차단됨)
- **P2. 업로드 멀웨어 방어 부재.** 매직바이트는 형식 검사지 보안 검사가 아니다. 특히
  **HWP는 한국에서 가장 흔한 악성코드 배달 수단** — 운영자가 그 파일을 열게 되는 구조라
  실제 위협. 최소: 스캔(ClamAV/클라우드 스캐너) 또는 "다운로드 전 경고+격리 정책".
- **P3. 성분·규제 데이터가 데모 수준.** 사전 ~80종/규제 8물질로는 실카탈로그에서
  대부분 unmatched → 완성도 점수 왜곡, 규제 스크리닝은 사실상 장님. CosIng 전체(~3만종,
  공개 CSV) 로드 + 검증된 LATAM 제한 목록 없이는 ④번 가치가 허구가 된다.
- **P4. 라이브 AI 경로가 한 번도 실행된 적 없음 + 골든셋 부재.** anthropic SDK 호출
  형태(structured outputs·fallbacks)는 미검증 코드이고, 정확도는 미측정. 파넬 실자료
  확보가 모든 것의 선행 조건.

### 중요 — 파일럿 중 빠르게 보완

- **P5. 운영자 검수 화면이 승인에 필요한 정보를 안 준다.** 큐에는 제품명·점수·플래그만
  보이고 원본 파일·사진·전체 초안 JSON 대조가 불가 — 인간 게이트의 "인간"이 볼 게 없다.
  초안 상세 뷰 + 원본 미리보기가 필요.
- **P6. 파일을 올리고 나면 아무도 못 본다.** 저장된 파일의 인증된 서빙 엔드포인트가 없어
  파트너도 운영자도 사진/문서를 다시 볼 수 없다(AI만 봄). 사진 미리보기는 기본 기대치.
- **P7. 조립(assemble) 단계 미구현 (설계-구현 격차).** v2 설계의 4단계 — 프로필들이 모이면
  카탈로그의 제품 N개 × 성분표 × 가격표를 묶어 복수 초안 자동 제안 — 가 빠졌다. 현재
  수동 추출은 제품 1개 초안만 만든다. "카탈로그 → 제품 20개 등록"이라는 핵심 절감
  시나리오가 아직 닫히지 않았다.
- **P8. 알림 루프 부재.** 파트너 제출 → 운영자는 큐를 열어봐야 알고, 승인/반려 → 파트너는
  링크를 다시 열어봐야 안다. 이메일 알림 없이는 "절감"이 아니라 "폴링 노동"이 된다.
- **P9. DB 실경로 미검증.** 마이그레이션 010·011과 신규 SQL(upsert 등)이 실제 Postgres에서
  실행된 적 없음(테스트는 DB-off·mock 경로). 로컬 포터블 Postgres로 bootstrap+왕복 1회가
  필요하다. needs_review 운영자 큐·재분석 버튼도 미구현.
- **P10. 잡 실패 운영성.** 인제스천 실패 시 재시도 정책 없음, 재인큐 도구 없음 —
  failed 프로필은 수동 SQL 없이는 영영 failed.

### 개선 — 완성도

- P11. 페이지네이션 없음(LIMIT 하드코딩), 파일 중복 dedup 없음(같은 파일 재분석 = 비용),
  완성도 점수의 구성요소 분해가 UI에 없음, 대시보드 파트너 목록 화면 없음(등록만 있고
  조회가 API뿐), hub 재로딩 시 업로드 선택 상태 유실.
- P12. docx/pptx/hwp 텍스트 추출 전처리 부재(파일명 분류에 그침 — 정직하게 표시는 됨).
- P13. 파트너 대상 고지(민감정보 외부 AI 전송, 데이터 보존)가 제품 안에 없다 — 온보딩
  문서 계획만 있음. 법적 최소선은 제품 내 고지.

## 4. Phase A — "회사에서 쓰기에 완벽" 로드맵 (파일럿 신뢰 확보)

순서 = 의존성 순. ①②는 코드만으로 가능, ③은 David 자료 필요.

1. **보안 경화 스프린트** (P1·P2 + 파트너 표면 rate limit + 파트너 행위 감사 로그):
   토큰 만료(기본 90일)+해시 저장+로그 마스킹, 업로드 스캔/격리, 인증된 파일 서빙(P6).
2. **데이터 기반 구축** (P3): CosIng 전체 CSV → 생성 시드(출처·버전 기록), 검증된
   MX/안데안 제한 목록 v1, HWP/docx/pptx 텍스트 추출(pyhwp·python-docx·python-pptx).
3. **가치 증명** (P4): 파넬 실자료 골든셋 → 라이브 개방 → 정확도·절감시간 실측 →
   7/17 이후 Gemini 3.5 Pro 맞대결 → 모델 확정. **"제품 1개 등록 55분 → 4분" 같은
   숫자가 나와야 이 시스템이 존재를 증명한다.**
4. **루프 완성** (P5·P7·P8): 운영자 초안 상세+원본 대조 뷰, assemble(카탈로그→복수 초안),
   이메일 알림(제출/승인/반려), needs_review 큐, 재분석 버튼, 잡 재시도.
5. **운영 안정화** (P9·P10): 실DB 왕복 검증, 업로드 백업(R2+수명주기 — 현재 "원본 영구
   보존" 원칙이 백업 없는 로컬 디스크와 모순), 모니터링(Sentry+uptime).

규모 감각: 집중 세션 4~6회 + David 입력(실자료·계정·규제 목록 검증 채널).

## 5. Phase B — SaaS 판매 수준 (솔직한 판단 포함)

**먼저 전략 판단: 범용 PIM으로 팔면 진다.** Akeneo·Salsify가 10년 먹은 시장이고 우리의
유연 속성 모델·신디케이션은 없다. **팔리는 모서리는 "K-뷰티(화장품) 수출 특화 파이프라인"**:
①한국 문서(HWP 포함) 네이티브 인제스천 ②INCI 자동 정규화 ③LATAM(확장: 미국 MoCRA·EU)
규제 사전 신호 ④인간 게이트 워크플로우. 이 조합은 Akeneo에 없고, 한국 화장품
제조·수출사(수천 개)와 해외 바이어/디스트리뷰터가 같은 고통을 겪는다. 규제 룰 DB를
**지속 갱신되는 콘텐츠 자산**으로 유지하는 것이 곧 해자(moat)다.

구조 변경 목록 (현 코드에서 불가능한 것들):

1. **멀티테넌시**: 지금은 Briwell이 유일한 운영자(단일 테넌트). 운영자 조직 모델 + 전면
   로그인(Supabase Auth, 역할), 테넌트별 데이터 격리(app-level+RLS), 스토리지 프리픽스·
   키 분리. 파트너 토큰 링크는 "테넌트의 벤더 초대" 기능으로 재배치.
2. **유연 스키마**: 카테고리 5종 enum·고정 draft 필드는 Briwell 전용이다. 테넌트별 속성
   스키마(커스텀 필드·카테고리 트리) 없이는 두 번째 고객부터 막힌다. 가장 큰 공사.
3. **과금·미터링**: AI 사용량 테넌트별 계측(프로필 usage는 이미 기록 중 — 기반은 있음),
   플랜/좌석/문서량 기준, Stripe.
4. **신뢰 스택**: DPA·보존정책·테넌트별 민감필드 암호화(공급가), 감사 로그 전면화,
   SOC2 지향 체크리스트, 상태 페이지.
5. **통합 표면**: 고객의 다운스트림(쇼피파이·ERP)으로 내보내는 웹훅/REST/CSV export —
   지금은 Briwell 내부 캠페인 시스템에만 연결됨.
6. **인프라**: 워커 분리(웹과 잡큐 분리 스케일), 오브젝트 스토리지 전면화, 큐 재시도·DLQ,
   SLO/모니터링.

규모 감각: 수주~수개월. 순서는 "파일럿에서 숫자 증명(Phase A) → 동종 1~2사 디자인
파트너로 무료 파일럿 → 그 요구로 멀티테넌시·유연 스키마 설계"가 맞다. **증명 없이
SaaS화 공사를 먼저 시작하는 것이 최대 함정.**

## 6. 우선순위 제안 (다음 3수)

1. **파넬 실자료 2~3부 확보** (David) — P4·P3의 선행 조건이자 가치 증명의 재료.
2. **보안 경화 + 데이터 기반 스프린트** (코드, §4-①②) — 실링크를 밖에 내보낼 자격 확보.
3. **골든셋 실측 + 모델 확정 + 루프 완성** (§4-③④) — "55분→4분" 숫자를 만들고, 그
   숫자가 Phase B(SaaS) 진행 여부를 결정한다.
