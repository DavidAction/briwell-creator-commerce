## 1. 문제 정의와 목표

**지금의 업무 흐름**: 브랜드사(파넬·아미코스메틱스·더말코리아 등)의 제품 정보 — 카탈로그 PDF,
제품 사진, 성분표(INCI), 가격/스펙 — 가 이메일·메신저로 산발적으로 도착하고, 운영자가 수작업으로
정리해 시스템에 입력한다. 제품 1개당 정리 시간이 크고, 포맷이 제각각이라 오류·누락이 생기며,
LATAM 수출 시 성분 규제 확인은 별도의 수작업이다.

**목표**: 브랜드사가 클라이언트가 된 후 **스스로 올리고 → AI가 구조화하고 → 운영자는 검수만
한다**. 정량 목표(파일럿 기준):

| 지표 | 현재(수작업) | 목표 |
|---|---|---|
| 제품 1개 등록 소요 | 운영자 30–60분 | 운영자 검수 3–5분 |
| 성분 규제 사전 확인 | 별도 수작업, 누락 위험 | 업로드 즉시 자동 플래그 |
| 데이터 완성도 | 비표준·측정 불가 | 제품별 완성도 스코어로 측정 |

**Briwell 원칙과의 정합**: creator_provided 채널과 동일한 거버넌스를 벤더 레인에 적용한다 —
fail-closed 검증, 원본 보존(감사 추적), AI는 초안만·인간 승인 게이트, 파생/추정 수치의 정직 표기.
비협상 제약과 충돌 없음(스크래핑·자동발송 무관). 규제 스크리닝은 **법률 자문이 아닌 참고 신호**로만
제공(비협상 제약 6).

## 2. 글로벌 벤치마킹 — 무엇을 훔치고 무엇을 버리나

| 시스템 | 핵심 패턴 | 우리 적용 | 버릴 것 |
|---|---|---|---|
| **Akeneo Supplier Data Manager** (공급사 데이터 온보딩의 글로벌 표준) | 공급사 전용 포털 + 공급사가 자기 포맷(Excel/CSV/PDF)으로 올리면 모듈형 워크플로우(추출→매핑→정규화→분류→검증)가 정제해서 PIM으로 밀어넣음. 온보딩 시간 50%+ 절감 사례 | **아키텍처의 뼈대.** 벤더는 편하게 올리고, 정규화 부담은 우리 파이프라인이 진다. 검증 모듈을 조합하는 설계(성분·클레임·이미지 각각 독립 검증기) | 별도 SaaS 구독. 우리는 FastAPI 안에 동일 패턴을 소규모로 구현 |
| **Salsify PXM** | 유연한 제품 속성 모델 + **채널별 완성도 스코어**(이 제품이 판매 준비에 몇 % 도달했나) + 속성을 한 번 정의하면 채널별 자동 매핑 | **완성도 스코어** — 벤더 대시보드의 중심 지표. "이 제품은 성분표가 없어 68%" 같은 즉각 피드백이 벤더 스스로 데이터를 채우게 만듦 | 대기업용 신디케이션 네트워크 |
| **Amazon Vendor Central** | 스펙 템플릿 + 벌크 업로드 + **업로드 즉시 오류 리포트** 반환 | 이미 우리 집 패턴(creator_provided CSV의 즉시 검증 리포트)과 동일 — 벤더 레인에도 템플릿+즉시 리포트 적용 | 벤더에게 부담을 전가하는 엄격한 스펙 강제(우리는 AI 추출이 부담을 흡수) |
| **UMMA** (K-beauty B2B 도매 1위, 180+ 브랜드) | 한국 브랜드들이 이미 B2B 플랫폼에 카탈로그·C.O.A.·수출 서류를 제공하는 관행이 정착됨 | 우리 벤더(한국 화장품사)가 이런 자료 제공에 익숙하다는 **시장 증거**. 요청 자료 목록을 UMMA 관행에 맞춰 설계하면 벤더 마찰 최소 | — |
| **CosIng** (EU 공식 성분 DB) | INCI 이름·CAS 번호·기능·**제한사항**이 담긴 공개 무료 CSV. "정보 제공 목적, 법적 효력 없음" 명시 | **성분 정규화 사전의 시드 데이터.** AI가 추출한 성분명을 CosIng 사전에 퍼지 매칭해 표준 INCI로 정규화 + 기능 태깅. 법적 효력 없음 문구는 우리 면책 문구의 선례 | EU 규제 로직 자체(우리 시장은 LATAM) |
| **INCIDecoder / Inference Beauty** | OCR + 표준 INCI 사전 퍼지 매칭이 성분표 파싱의 검증된 패턴. 멀티모달 AI가 레이아웃을 사람처럼 읽는 것이 최신 표준 | Gemini 멀티모달(이미 우리 어댑터에 inlineData 구현됨)로 PDF/성분표 이미지 → 구조화 JSON | 소비자용 성분 해설 콘텐츠 |

**규제 벤치마킹(우리 시장 3국)** — 스크리닝 기능의 근거:

- **멕시코 COFEPRIS**: 허용/금지 성분 목록 대조 필수, 라벨 규정 NOM-141(스페인어 표기), 수입 전
  Notice of Operation. 성분 비준수 시 재배합 전까지 시장 진입 불가.
- **페루 DIGEMID**: NSO(의무 위생 통보) 필요, 현지 대리인(droguería) 필수, 등록 유효 7년.
- **핵심 발견 — 안데안공동체 Decision 833**: 페루·에콰도르(ARCSA)·콜롬비아·볼리비아는 한 국가의
  NSO를 상호 인정. **페루 NSO 하나가 에콰도르 진입도 연다** → 성분 사전 스크리닝의 투자 대비
  효과가 2개국 이상에 걸침.

## 3. 전체 그림

```
[벤더(한국 브랜드사)]
   │ ① 업로드: 카탈로그 PDF · 제품 사진 · 성분표 · 스펙/가격 xlsx (자기 포맷 그대로)
   ▼
[벤더 포털 (KO, 신규)]────────── 완성도 스코어 · 업로드 이력 · AI 초안 확인/수정
   │ ② 원본 저장(해시·감사 추적) + 업로드 즉시 기본 검증 리포트
   ▼
[AI 파이프라인 (기존 어댑터 확장)]
   ②-a 추출: Gemini 멀티모달 → 구조화 JSON (드라이런 기본, 듀얼 게이트)
   ②-b 정규화: INCI 사전(CosIng 시드) 퍼지 매칭 · 카테고리 분류
   ②-c 검증: 스키마+비즈니스 룰, 신뢰도 낮으면 사람 큐로 (fail-closed)
   ②-d 규제 신호: LATAM 금지/제한 성분 룰테이블 대조 → 플래그 (법률 자문 아님)
   ▼
[벤더 확인] ③ AI 초안을 벤더가 확인·수정 (자기 제품은 자기가 제일 잘 앎)
   ▼
[운영자 검수 (기존 대시보드에 화면 추가)] ④ 승인/반려 — 인간 게이트, 자동 확정 없음
   ▼
[확정 카탈로그 (기존 product_catalog 확장)]
   → 캠페인 매칭 · 크리에이터 브리프 · 클레임 검수(기존 claims-check 재사용) · 커머스 연동
```

**기존 자산 재사용 지도** (새로 만들 것을 최소화):

| 기존 자산 | 벤더 포털에서의 역할 |
|---|---|
| `product_catalog` 테이블 + `/products` 라우터 (허용/금지 클레임 필드 보유) | 확정 카탈로그의 저장소 — 확장하되 신규 발명 없음 |
| creator_provided 인테이크 패턴 (fail-closed 동의 검증·즉시 리포트) | 벤더 업로드 검증의 설계 원형 |
| 크리에이터 포털 (토큰 링크·필드 화이트리스트·정직한 실패) | 벤더 접근 모델의 선례 + The Well UI 계열 |
| Gemini 어댑터 (드라이런 게이트·inlineData 멀티모달·invocation log) | 추출 엔진 — 프롬프트/스키마만 추가 |
| AI eval harness + calibration (골든셋 측정) | 추출 정확도의 측정 가능한 품질 게이트 |
| outreach claims-check | 벤더가 올린 마케팅 클레임의 사전 검수 재사용 |
| 듀얼 라이브 게이트 관례 (`NEWS_RSS_*` 패턴) | `VENDOR_AI_*` 게이트 — 드라이런 기본, 프로덕션 명시 개방 |
| 파생/추정 정직 마커 · 쓰기 확인 게이트 · KPI 스트립 | 운영자 검수 화면에 동일 적용 |

## 4. 사용자와 플로우

**페르소나**
1. **벤더 담당자** (한국어, 브랜드사 마케팅/수출 담당) — 데스크톱 위주, 엑셀·PDF에 익숙.
2. **Briwell 운영자** — 기존 대시보드 사용자. 검수 큐가 새 화면.
3. **(소비자로서의) 기존 시스템** — 확정 제품 데이터가 캠페인 매칭·크리에이터 브리프에 흘러감.

**벤더 여정**: 초대(운영자 발급) → 회사 프로필 확인 → 제품 업로드(파일 드롭 or 폼) →
AI 초안 검토·수정 → 제출 → (운영자 승인 후) 확정 카탈로그에서 자기 제품 상태·완성도 확인.

**요청 자료 목록(UMMA 관행 기준, 벤더 온보딩 문서로 제공)**: 제품 카탈로그(PDF), 제품별 이미지
(흰 배경+연출컷), 전성분(INCI, 국문+영문), 용량/제형/유통기한, 소비자가/공급가, (있으면)
C.O.A.·기능성 인증·수출 이력.

## 5. AI 파이프라인 설계 (핵심 차별점)

**5단계, 각각 독립 모듈** (Akeneo 모듈형 워크플로우 패턴):

1. **추출 (extract)** — Gemini 멀티모달: PDF 페이지/이미지 → 제품 단위 구조화 JSON
   (제품명·브랜드·카테고리·용량·성분 리스트·클레임 후보·가격). 페이지별 신뢰도 자기보고 +
   calibration guidance(기존 CALIBRATION_GUIDANCE 확장). 드라이런 시 결정적 샘플 반환.
2. **정규화 (normalize)** — 성분명을 INCI 표준으로: CosIng CSV 시드 사전(약 3만 항목)에
   정확→퍼지 순 매칭. 미매칭 성분은 `unmatched`로 정직하게 남김(추측 금지). 카테고리는 기존
   ProductCategory enum으로 분류 + 신규 카테고리 후보는 별도 플래그.
3. **검증 (validate)** — 스키마 검증 + 비즈니스 룰(필수 필드, 이미지 해상도, 클레임 문구가
   claims-check 금지 목록에 걸리는지). 실패는 항목별 한국어 리포트로 벤더에게 즉시 반환.
4. **규제 신호 (screen)** — `regulatory_ingredient_rule` 룰테이블(국가×성분×제한 유형)과 대조.
   v1 시드: 멕시코 금지/제한 목록 + 안데안 Decision 833 부속서. 결과는 **신호 등급**
   (`blocked_candidate` / `restricted_candidate` / `no_flag`)으로만 — 화면에 "법률 자문이 아니며
   수입 전 전문 검토 필요" 상시 표기.
5. **완성도 (score)** — Salsify식 완성도 스코어: 필수 필드 가중 합산(성분 30%·이미지 20%·
   기본정보 20%·클레임 검수 15%·규제 신호 무플래그 15%). 벤더 대시보드의 중심 지표.

**품질 게이트**: 파일럿 전 골든셋(실제 카탈로그 3종 × 수작업 정답) 구축 → eval harness로 추출
정확도·과신도 측정 → 필드별 정확도 90% 미만이면 해당 필드는 AI 초안 대신 빈 값+수동 입력 유도
(정직 원칙). AI 호출은 전부 invocation log에 기록(기존 관례).

## 6. 데이터 모델 스케치 (마이그레이션 010)

```
vendor_company        업체: 이름, 사업자 정보, 담당자, 상태(active/suspended)
vendor_access_token   크리에이터 포털과 동일 패턴: 업체당 활성 1개, 회전=폐기 (파일럿 A안일 때)
vendor_upload         원본 파일: 파일명, 타입, 크기, sha256, 저장 경로, 업로더, 상태
                      (uploaded → extracted → vendor_confirmed → approved / rejected)
vendor_product_draft  AI 초안 + 벤더 수정본 (JSONB, 버전 이력) → 승인 시 product_catalog로 승격
product_ingredient    확정 제품의 성분: INCI 표준명, 표기 순서, 매칭 상태, CosIng 참조
ingredient_dictionary CosIng 시드 + 수동 보강 (INCI명, 별칭, 기능, CAS)
regulatory_ingredient_rule  국가 × 성분 × 제한유형 × 근거 출처 × 시드 버전
ai_extraction_run     업로드 → 초안 이력: 모델/프롬프트 버전, 신뢰도, 토큰 비용 (감사 추적)
vendor_review_decision 운영자 결정: 승인/반려 + 사유 (인간 게이트 기록)
```

원본 파일 저장소는 결정 포인트(§9-②). 원본은 절대 삭제하지 않음(감사 추적) — creator_provided
와 동일 철학.

## 7. API·화면 스케치

**신규 라우터 `vendor_portal.py`** (기존 portal.py 관례 준수):

```
운영자 측 (RBAC: admin/operator/campaign_manager)
  POST   /vendors                          업체 등록
  POST   /vendors/{id}/tokens              접근 토큰 발급·회전 (A안)
  GET    /vendors/{id}/review-queue        검수 큐
  POST   /vendors/review/{draft_id}        승인/반려 → 승인 시 product_catalog 승격

벤더 측 (토큰 게이트, 자기 회사 데이터만 — 필드 화이트리스트)
  GET    /vendor-portal/me?token=          회사 프로필 + 제품 목록 + 완성도
  POST   /vendor-portal/uploads?token=     파일 업로드 (타입/크기 검증, 해시 기록)
  POST   /vendor-portal/uploads/{id}/extract?token=   AI 추출 실행 (듀얼 게이트)
  PUT    /vendor-portal/drafts/{id}?token= 초안 수정·확정 제출
```

**벤더 포털 UI** (신규 정적 앱 `work/briwell_vendor_app/`, KO, The Well 아이덴티티 —
크리에이터 포털과 형제 표면, 단 데스크톱 우선):
대시보드(완성도 스코어·검수 상태) / 제품 목록 / 업로드 & AI 초안 확인(원본 미리보기와 추출
결과를 나란히, 필드별 신뢰도 표시) / 제출 이력.

**운영자 대시보드**: 기존 앱에 "벤더 검수" 화면 1개 추가 — 검수 큐, 원본 대조 뷰, 승인/반려
(쓰기 확인 게이트), 규제 플래그 요약.

UI 컨셉 샘플(2–3안)은 **전략회의 승인 후** 제작한다(합의 프로세스). 단, 홈페이지 테마 투표가
진행 중이므로 — 벤더 포털은 기업 인프라 표면이라 **테마 결과와 무관하게 The Well 계열 유지**를
권장(크리에이터 포털과 동일 판단). 이것도 결정 포인트.

## 8. 접근·보안 설계

| | A안: 토큰 개인링크 (크리에이터 포털 패턴) | B안: Supabase Auth 계정 (이메일+비밀번호) |
|---|---|---|
| 구축 속도 | 즉시 (마이그레이션 009 패턴 복제) | OIDC 스캐폴드 있으나 가입/초대 플로우 신규 |
| 보안 | 링크 유출 = 접근 유출. 단 **쓰기 권한이 있는 표면이라** 크리에이터 포털(읽기 전용)보다 리스크 큼 | 표준 B2B. 세션 관리·비밀번호 재설정 필요 |
| 벤더 UX | 링크 클릭 한 번 | 로그인 절차. 반복 사용 벤더에겐 오히려 자연스러움 |
| 권장 | **파일럿(벤더 1–2사)**: A안 + 짧은 만료 + 회전 킬스위치 + 업로드 rate limit | **정식**: B안 전환 (Phase 3) |

공통 안전장치: 파일 타입 화이트리스트(pdf/png/jpg/xlsx/csv)·크기 상한·매직바이트 검사, 벤더별
데이터 격리(타사 데이터 구조적 차단 — 포털 화이트리스트 패턴), 가격 등 민감 필드는 운영자
화면에만, 업로드 파일은 실행 불가 경로에 저장.

## 9. 결정 포인트 (David — 전략회의 안건)

1. **범위 확정**: 위 그림(업로드+AI 구조화+검수+규제 신호)이 맞나? 빼거나 더할 것?
2. **파일 저장소**: 파일럿은 서버 로컬 디스크(Render persistent disk, 간단·저렴) vs 처음부터
   S3 호환(Cloudflare R2 등, 확장성·백업 유리). **권장: 파일럿 로컬 + 저장 경로 추상화로 R2
   전환 대비.**
3. **접근 방식**: §8의 A안(파일럿) → B안(정식) 2단계 권장. 동의하는지, 아니면 처음부터 B안?
4. **1호 벤더와 시작 자료**: 파넬·아미·더말 중 어느 회사 자료로 골든셋을 만들지. (실 카탈로그
   3종이 골든셋 재료 — 이미 랜딩용 공식 사진 확보 경로가 있는 파넬이 유력해 보임)
5. **규제 신호 시점**: Phase 1 포함(권장 — 차별점의 핵심) vs Phase 2로 미룸.
6. **UI 방향**: The Well 계열 유지(권장) vs 홈페이지 테마 투표 결과 반영. 승인 시 컨셉 샘플
   2–3안 제작 진행.
7. **명칭**: "벤더 포털" / "브랜드 파트너 허브" / 기타.
